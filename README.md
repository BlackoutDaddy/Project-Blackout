# Project Blackout

**A rugged, modular survival computing and communications platform.**

Project Blackout is an experimental hardware and software project focused on building a portable, resilient field computer and communications ecosystem for situations where conventional infrastructure may be unavailable or unreliable.

The goal is to combine **local computing, resilient communications, navigation, information, and network awareness** into a system that can be useful to families, outdoorsmen, emergency-preparedness users, and anyone who wants greater independence from traditional infrastructure.

---

## The Blackout Ecosystem

### 🖥️ Blackout

The primary field computer and command node.

Blackout is being developed around a Raspberry Pi-class computer and is intended to provide:

- Local and offline computing
- Offline maps and navigation
- Meshtastic / LoRa communications
- GPS
- Network and node monitoring
- Local data storage
- Future offline AI/LLM capabilities
- Portable power
- A ruggedized, field-ready enclosure

Blackout is intended to act as the primary computing and network-management platform within the ecosystem.

### 🎒 Scout

A small, portable communications node designed to be carried by an individual.

Scout is intended to provide a lightweight way to participate in the Blackout communications network without carrying the full Blackout computer.

### 🚙 Rover

A vehicle-mounted communications node designed to extend the range and availability of the Blackout network.

Rover is intended to provide a persistent node in a vehicle while Blackout and Scout nodes are being carried elsewhere.

## Design Philosophy

Blackout is being developed around several core principles:

**Resilience** — The system should remain useful when internet, cellular service, or other infrastructure is unavailable.

**Modularity** — Individual components should be replaceable, upgradeable, and useful on their own.

**Practicality** — The system should solve real problems rather than simply being a collection of interesting technology.

**Fieldability** — Hardware should be designed to survive actual use outside of a workbench.

**Repairability** — Wherever practical, the system should use understandable and replaceable components rather than relying on proprietary infrastructure.

**Learning** — Blackout is also a hands-on learning project. Development is being used to build practical knowledge in electronics, Linux, networking, programming, radio communications, and system design.

**Test in the real world** — Ideas are prototypes until they have been tested outside of the workbench.

---

## Why Blackout?

Modern life depends heavily on centralized infrastructure.

Blackout explores a simple question:

> **What useful technology could you still have if the infrastructure around you stopped working?**

The goal isn't to replace the internet or build a complicated communications system for its own sake.

The goal is to build something **practical, understandable, modular, repairable, and useful in the real world.**

## Current Status

🚧 **Early development**

Blackout is currently an experimental prototype and learning project.

Current development is focused on:

- Raspberry Pi-based computing
- Meshtastic and LoRa communications
- Scout and Rover node development
- Power systems
- Hardware integration
- Linux
- Networking
- Offline mapping
- System monitoring
- Field testing

Many aspects of the system are experimental and subject to change.

Documentation, designs, software, and hardware will evolve as the project is built and tested.

---

## Development Approach

Blackout is being built incrementally rather than designed entirely on paper.

The project is intended to document both **what works and what doesn't**.

Experiments, failed approaches, hardware revisions, software changes, and lessons learned are all part of the development process.

The goal is not simply to produce a finished device, but to understand the system well enough to build, maintain, troubleshoot, and improve it.

---

## AI-Assisted Development

AI tools are used during the development of Project Blackout as a learning and development aid.

AI may be used for research, brainstorming, documentation, troubleshooting, code examples, and explaining technical concepts.

Generated code and recommendations are reviewed, tested, modified, and integrated by the project developer.

The goal is not to have AI build Blackout independently, but to use AI as a tool while developing the skills necessary to understand, maintain, and eventually build the system independently.

**AI-assisted does not mean AI-developed.**

---

## Project Status & Contributions

This project is currently being developed independently and is **not yet an open-source project or commercial product**.

The repository is being used to document development, experiments, ideas, and progress.

As Blackout matures, the approach to community participation, contributions, and licensing may evolve.

---

## The Long-Term Vision

The long-term goal is to develop Blackout into a complete ecosystem of hardware and software that can provide useful computing, information, and communications capabilities without depending entirely on conventional infrastructure.

The project is still at the beginning.

**Build it. Test it. Break it. Learn from it. Improve it.**
